研究原型與工程實作

資安演練中的測試程式能否執行，往往受到防毒軟體（AV）與端點防護影響。檔案是否被攔截、執行時是否產生告警，以及測試端能否收到連線，都是需要記錄的結果。

Win Steg GUI 是碩士研究中開發的 Windows C++ 原型，結合影像藏密、AES 加解密與編譯階段混淆。介面使用 FLTK 顯示影像與載入狀態，測試則在虛擬機中進行，並保留 VirusTotal 與 Hybrid Analysis 的分析紀錄。

設計與資料流程#

圖 1｜使用 FLTK 建立的影像顯示介面，包含桌面視窗、分頁與影像載入功能。

程式分為桌面介面、影像處理與共用工具三部分。介面操作與資料處理的關係如下：

使用者操作 → 桌面介面 → 影像／資料處理 → 結果與狀態回饋

  • 桌面介面 — 使用 FLTK 建立分頁與操作按鈕，顯示影像及載入狀態。
  • 影像處理 — 使用 Blimp 操作 BMP 影像，整合影像藏密與資料轉換。
  • 共用工具 — 集中管理影像、檔案與日誌相關工具，供各模組使用。

執行時序#

圖 2｜原型的執行時序，呈現 GUI 與背景工作的協作關係。

本專案使用 APC（Asynchronous Procedure Call，非同步程序呼叫）讀取藏密影像、提取資料與解密，由 GUI 的載入錯誤觸發，後續執行則交由另一條執行緒處理。錯誤處理 callback 會同步等待 APC 工作完成，因此這段期間 GUI 事件循環會暫停。

「2th Examiner」分頁：以載入失敗觸發背景工作#

介面的第二個分頁標示為 2th Examiner。啟動時，程式會刻意載入不存在的影像檔（assets/images/lena9.bmp），透過載入失敗呼叫已註冊的 error handler，讓先前建立並掛起的 APC 執行緒繼續工作。

圖 3｜第二個分頁「2th Examiner」，它負責產生載入錯誤以觸發背景工作。

因此，第二個分頁的載入錯誤是預先安排的觸發事件，並非測試中意外發生的故障。

技術與工程考量#

本專案使用的主要工具與方法如下：

  • 影像處理： 使用 Blimp 操作 BMP 影像，藏密採用最基本的 2-bit LSB 直接替換；影像品質以 MSE、PSNR 與 SSIM 評估。
  • 加解密： 使用 Tiny-AES-c 處理 AES 加解密。
  • 工程實作： 以 C++14、FLTK 1.3.9 與 CMake 3.30.1 建立桌面原型；GUI 套件透過 vcpkg 安裝。

編譯階段混淆：Akira-Obfuscator#

編譯階段使用基於 LLVM 的 Akira-Obfuscator，搭配相容的 Clang 17.0.6，對 C++ 程式進行程式碼層級混淆。影像藏密處理的是酬載的儲存方式，編譯混淆則改變程式結構與編譯後的二進位特徵。

CMakePresets.json 的 Release preset 啟用了以下四項混淆功能：

  • 間接分支： 將直接分支跳轉改為間接跳轉，改變控制流程的表示方式。
  • 間接函式呼叫： 將直接函式呼叫改為透過函式位址間接呼叫，使呼叫關係較難從靜態程式碼直接判讀。
  • 間接全域變數存取： 將全域變數的直接存取改為間接存取，改變變數位址的取得方式。
  • 控制流程平坦化： 將原有的分支結構改為由狀態分派控制的流程，增加還原原始執行順序的難度。

驗證方式與結果解讀#

測試樣本的選擇#

測試使用 msfvenom 產生的 Windows x64、非分階段（unstaged）的 TCP reverse shell。Shellcode 本身未再套用編碼器、額外混淆，也未改用其他混淆版本；儲存時仍經過本專案的 AES 加密與影像藏密。

選用這個樣本，是因為未經處理的版本具有明顯的已知特徵，適合作為對照。保留 shellcode 原本的內容，便能把測試重點放在加密、藏密、載入與編譯混淆等其他步驟整合後的效果。不過，這次沒有逐項移除各步驟做對照測試，因此只能觀察整套流程的結果，無法據此判定每個步驟各自的貢獻。

影像品質比較#

藏密採用最簡單的 2-bit LSB 直接替換法，將 RGB 各色彩通道的最低兩個位元替換為待藏入的資料。測試使用的 512 × 512 BMP 影像，對本次 msfvenom shellcode 及加密後的資料而言，容量已相當足夠，只需修改影像中的一小部分。

這個方法沒有抗干擾設計；加入雜訊、有損壓縮、縮放或其他會改變像素值的處理，都可能破壞藏入的資料。本專案將它用作 AV 測試中的簡化藏密流程，測試時保留原始 BMP，不以壓縮或影像處理後仍可還原資料為目標。

影像差異使用 DiffImg 檢視，並以 MSE、PSNR 與 SSIM 量測相似度。下圖中的黃色部分是比較工具標示的差異，非原圖本身的顏色。

圖 4｜處理前後的影像比較：左側為原載體，右側為處理後影像，上方為局部差異的放大檢視。

本次測試影像的品質量測

指標記錄值
均方誤差（MSE）0.005891
峰值訊號雜訊比（PSNR）70.43 dB
結構相似性（SSIM）0.999994

MSE 越接近 0，代表平均像素誤差越小；PSNR 越高，代表相對於原圖的失真越低；SSIM 越接近 1，代表亮度、對比與結構越相似。本次數值反映的是少量資料嵌入後，整張影像的變化很小。這些指標不衡量抗干擾能力，也不能用來判斷藏密分析工具或 AV 是否能偵測出其中的資料。
